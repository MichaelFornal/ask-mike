## Global Constraints

**Repo and privacy**
- This repo is public. No jb path, no home-directory path, no server IP and no private material goes in a tracked file. Those live in the companion.
- Commits use the noreply identity. `tools/scan_public.py` and the copycheck pass on every commit here.
- The visitor-log notice stays exactly one line: "Questions are saved so Mike can read them." That's on ask.forn.al. forn.al's form carries its own version, set in the copy pass.

**Numbers**
- On ask.forn.al and in the README: only a fact's display string from `facts.json`, checked by `askmike.facts.copycheck`.
- On forn.al: only a counted fact, checked by forn.al's page gate (companion §1).
- On the résumé: only a fact-backed number, checked by the résumé gates (companion §2). Ask Mike's numbers come from this repo's `facts.json` through a command, as DTD's do.

**Pages**
- There's no JavaScript on forn.al or on ask.forn.al.
- forn.al's only CSP change is `form-action 'none'` → `form-action https://ask.forn.al`.
- ask.forn.al's CSP is unchanged.
- **Form contract (verbatim from the M3 plan):** `POST https://ask.forn.al/ask`, urlencoded, with field `q` (the text) and an optional field `prev` (an answer id). forn.al's form sends `q` only.
- **Voice.** Ask Mike's pages are third person, the way the AI speaks ("Mike built…"). forn.al keeps its own voice, set in the copy pass.
- **Style.** Every new line of copy passes the slop rules: no hype adjectives, no em dashes, no "end to end", no "leverage", no filler openers. There's no score or verdict anywhere.

**DTD (spec §10)**
- deals.forn.al keeps serving, with no redirect and no "retired" note.
- DTD stays on the Projects page, on the résumé as the second project (trimmed, and the first entry cut for space), and pinned on GitHub.
- The counted facts behind DTD's figures stay.

**Who runs what**
- Mike runs every production or publishing command:
  - `git push`
  - `deploy/push.sh`
  - `vercel deploy` and `vercel promote`
  - `gh api -X PATCH`
  - GitHub pins, which are set only in the web UI

  He runs them with `!` (the auto-mode classifier blocks them for Claude).
- Claude runs local builds, gates, smoke tests and read-only `curl` and `ssh` checks.

**Money**
- No new API spend. End-to-end checks use a handoff or an over-long input, which make no model call. The smoke test's `--ask` makes one Haiku call (about $0.0005).

## Review Focus

1. **The box posts nowhere.** If forn.al's CSP still says `form-action 'none'`, or the form's action drifts from the contract, the browser silently blocks the submit. Task 2's gate refuses the page, and Task 6 checks the preview's real header.
2. **A long paste from forn.al.**
   - A posting over the app's character cap gets the too-long page.
   - A body over 96KB gets Caddy's 413 fallback page.

   Neither may show a browser or Caddy error. Task 6 posts both from the forn.al preview's form.
3. **Phone width and dark mode.** The new textarea and button must fit 375 px without horizontal scroll, and stay readable in both themes. Task 3 takes screenshots at 375 and 1280 px in light and dark.
4. **Uptime monitors and link checkers send `HEAD`.** A 405 reads as down. Task 1 makes every `GET` route answer `HEAD`.
5. **A results number drifts from the evals.** A later eval refresh changes `facts.json`, and a page with copied figures would go stale. The page renders from `facts.json` at start, a missing key stops the app from starting (so push reverts), and Task 1 tests both.
