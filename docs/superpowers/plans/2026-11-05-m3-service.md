# M3 Service Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve Ask Mike at `ask.forn.al`, on the server it shares with Deal Terms Desk (DTD). The site uses server-rendered HTML with no JavaScript. Every model call goes through a spend ledger capped at $15.00 a month. It has per-address rate limits, an answer cache, a private visitor log and a static fallback page, so a visitor never sees an error. It is live behind an unlinked URL, and both Ask Mike's smoke test and DTD's pass.

**Architecture:**
- **DTD release first.** DTD ships a maintenance release first, which splits the box's Caddy config. The base `/etc/caddy/Caddyfile` keeps DTD's global log filter and imports `/etc/caddy/sites/*.caddy`. Each app then installs only its own site file.
- **The service.** Ask Mike's service is a FastAPI app. It runs as user `ask` on 127.0.0.1:8001 and reuses DTD's patterns: the spend ledger, rate limits, cache, release layout, push script and smoke test.
- **The desk.** One "desk" object sits between the page and the M2 `Answerer`. It applies the limits, the cache, the metered model calls and the visitor log.

**Tech Stack:**
- Python 3.12, uv, pytest.
- New runtime dependencies: `fastapi` and `uvicorn` (pinned to the minor versions DTD's `uv.lock` resolves), and `jinja2>=3.1,<4`.
- On the box: Caddy, systemd and SQLite, on Ubuntu 24.04.

## Global Constraints

**Repo and privacy**
- The repo is public. No server IP address and no private file goes in a tracked file. The ssh target comes from `ASK_HOST` (for example `root@<host>`). DTD's own scripts use `DTD_HOST`.
- The gate-config bundle (`$ASK_PRIVATE_DIR/deploy/gate_config.json`) goes to `/etc/ask/gate_config.json` (owner root, group ask, mode 640). It never enters a release directory, a log or a command's output.
- **Visitor log** (spec §7):
  - It holds question text, the pasted job description, the timestamp, the answer id and the outcome, and no IP address.
  - It lives only in `/var/lib/ask/visits.db` on the box and `$ASK_PRIVATE_DIR/logs/`, never in the repo, CI or deploy logs.
  - The page carries exactly one line about it: "Questions are saved so Mike can read them."
- Rate limits key on the visitor's address in memory only. Nothing persists or logs an address. Caddy's global log filter deletes `request>remote_ip`, `request>client_ip`, `request>uri` and `request>headers`. The service logs one JSON line per request (route, outcome, ms), never the address or the text.
- Every number printed in a tracked doc or page comes from `facts.json`. Copycheck and the scan pass on every commit.

**Shared server (CLAUDE.md, verbatim values)**
- **Ask Mike's own resources:**
  - system user `ask`
  - `/srv/ask/{releases,bundles}`, `/var/lib/ask` and `/etc/ask/env` (root, 600)
  - `ask.service` on 127.0.0.1:8001 (DTD holds 8000)
  - its own `MemoryMax`, spend ledger and Anthropic API key
- **Provisioning is additive.** Don't rewrite the sshd, journald or ufw drop-ins (`10-dtd.conf`) that DTD's provision already set. Never run `apt-get upgrade` from Ask Mike's provision.
- **Caddy files.** Ask Mike installs only `/etc/caddy/sites/ask.caddy`. It never writes `/etc/caddy/Caddyfile` or another site's file. DTD installs the base file and `/etc/caddy/sites/deals.caddy`. Each push validates the combined config before it installs and reloads.
- **Done means both smoke tests pass.** M3 is done only when Ask Mike's `deploy/smoke.py` and DTD's `deploy/smoke.py https://deals.forn.al` both pass.

**Money**
- The month budget is $25 all-in: $7.09 server + $2.91 DTD model cap + **$15.00 Ask Mike model cap**.
- The day cap is the month cap times `day_cap_share` 0.1, which is $1.50 and matches DTD's ratio. Both caps are facts, and push refuses when the box's env differs.
- Every model call reserves its worst case before the call and settles from usage after. The rules (`MAYBE_BILLED = ("timeout", "connection")`) are:
  - an error with no usage whose kind is in MAYBE_BILLED, or a reply with empty usage, books the worst case;
  - any other error with no usage is released.
- The worst case comes from `askmike/llm/prices.py` `worst_case_usd` with the call's own model prices.

**Answering**
- The models come from `askmike/answer/settings.json` (question → claude-haiku-5-5, jd → claude-sonnet-5-5; effort medium; max_tokens 8000). `load_answer_settings` validates it.
- Live calls go through `askmike/llm/api_runner.make_api_runner(max_tokens=8000, timeout=ASK_API_TIMEOUT_S)`. They are never wrapped in `ledgered_runner`, so M1's extraction parse retry is a real second call.
- **What a visitor can see.** A visitor only ever sees one of:
  - gated claims;
  - the fixed strings in `askmike/answer/config.py`;
  - the fallback (`askmike/answer/fallback.json`);
  - a static fallback page served by Caddy.

  There is no error page and no stack trace. Rate limits, the cap, busy slots and API failures all show the fallback page.

**Page**
- No JavaScript anywhere on ask.forn.al (spec §3 and §7). The CSP has no `script-src`.
- **Form contract with forn.al (used in M4):** `POST https://ask.forn.al/ask`, urlencoded, with field `q` (the text) and an optional field `prev` (an answer id).
- All visitor and model text is HTML-escaped (Jinja2 `autoescape=True`). There are no inline scripts, inline styles or event handlers.

**Deploys**
- A push to the box, a provision run, a DNS change and the env file are Mike's calls. The plan stops for his go before any of them (Task 9).
- The Anthropic API key is never seen by Claude. Mike writes `/etc/ask/env` himself.

## Review Focus

1. **A deploy of either app deletes the other site.** DTD's push writes only the base Caddyfile and `deals.caddy`. Ask Mike's push writes only `ask.caddy`. Each validates the combined config first. Pinned in Task 1 and Task 7.
2. **A pasted job description tells the model to add a link.** No link reaches the page unless a cited unit holds it, and forn.al and its subdomains are always allowed. Pinned in Task 2 by the link test and a URL canary injection row.
3. **The cap runs out between extraction and answer on a job description.** The visitor gets the fallback page. The extraction spend is settled, the answer reservation is never made, and the log records `fallback` / `budget`. Pinned in Task 5.
4. **The app is restarting or has crashed when a form arrives.** Caddy serves the static `fallback.html` for upstream 502, 503 and 504, never Caddy's error page. Pinned in Task 6 (the file) and Task 7 (the Caddy rule and the smoke test).
5. **One address bursts, or forges `X-Forwarded-For`.** The visitor gets the fallback page with status 429 and `Retry-After`. A forged header doesn't reset the bucket. Pinned in Task 5 (the desk) and Task 7 (the smoke test).

**Interfaces:**
- **`AnswerCache(db)`** works as follows:
  - `key(kind, model, text, prev_text, ids: dict) -> str` is the sha256 of a JSON list holding:
    - `kind` and `model`
    - effort and max_tokens
    - the whitespace-collapsed `text`, and `prev_text`

  - **Columns:** `id TEXT PRIMARY KEY`, `ts TEXT` (UTC ISO), `kind`, `input TEXT`, `prev_id TEXT`, `outcome`, `fallback_reason`, `model`, `served_from` (`model | cache | none`), `turn_text TEXT`, `kept_json TEXT` and `template_sha`. There is no column for an address, a header or a user agent.

### Task 5: The desk, with metered calls, limits, cache and log

**Files:**
- Create: `askmike/service/desk.py`
- Modify:
  - `askmike/llm/api_runner.py`: `KINDS` gains `"budget"`.
  - `askmike/answer/answerer.py`: a `RuntimeError` whose `kind == "budget"` gives `fallback_reason "budget"`. `Outcome.fallback_reason` gains `budget | busy | limited`.
- Test: `tests/test_desk.py`

**Interfaces:**
- **`metered(runner, budget, max_tokens) -> runner`.** For each call:
  1. Compute `worst = worst_case_usd(load_prices(model), len(prompt), max_tokens)`.
  2. `rid = budget.reserve(worst)`. If that returns `None`, raise `RunnerError("budget", …)`.
  3. Call the model, then settle by these rules:
     - **Success:** settle `cost_usd(prices, usage)`. If usage is empty, settle `None`.
     - **RunnerError carrying usage:** settle its cost.
     - **RunnerError with no usage, kind in MAYBE_BILLED:** settle `None`.
     - **Any other error:** release the reservation.
- **`Served(outcome: Outcome, visit_id: str, status: int, served_from: str)`.**
- **`Desk(answerer, budget, cache, visits, asks: Buckets, fresh: Buckets, slots: Slots, settings, ids)`.** `ids` is `{git_sha, corpus_sha, index_sha, template_sha, gate_sha}`. The `answerer` is the M2 `Answerer` with the settings' model map, built on `metered(make_api_runner(...), budget, MAX_TOKENS)`.
- **`Desk.ask(text: str, prev_id: str | None, client: str) -> Served`** runs these steps in order:
  1. **Route.** `empty`, `too_long` and `handoff` are logged and returned with status 200. They make no call, take no limit and use no budget.
  2. **Rate limit.** If the per-address ask bucket is closed, return fallback `limited` with status 429, and the app sets `Retry-After`.
  3. **Previous turn.** `previous = visits.previous(prev_id)`.
  4. **Cache.** A hit returns `served_from "cache"` with status 200, even when the budget is reached.
  5. **Busy.** If no slot is free, or the global fresh bucket is closed, return fallback `busy` with status 503.
  6. **Answer.** Call `answerer.ask(text, previous)`, then cache the outcome if it is an `answer`.
  7. **Log and return.** Record the visit and return with status 200, fallback included.
- **`Desk.health() -> dict`** returns `{ok, git_sha, corpus_sha, index_sha, template_sha, models, budget: "ok"|"reached", rss_mb}`. It holds no amounts. `budget` is `budget.state(worst_case_usd(<jd model prices>, typical_prompt_chars, MAX_TOKENS))`.

### Task 6: The answer page, evidence pages and the static fallback

**Files:**
- Create:
  - `askmike/service/app.py` (`create_app(config=None, desk=None)`, a uvicorn factory)
  - `askmike/service/pages.py`
  - `askmike/service/templates/{base,home,answer,evidence}.html`
  - `askmike/service/static/style.css`, copied from DTD `site/static/style.css`, which already follows forn.al's design, with a provenance comment
  - `askmike/service/__main__.py`, with steps `site --out DIR` and `config-check`
- Test: `tests/test_app.py`, `tests/test_pages.py`

**Interfaces:**
- **Routes.** Every HTML route answers with a page, never an error page. There are no others: `/docs` and `/openapi.json` return 404.
  - **`GET /`.** The home page: the box, a form posting to `/ask` with field `q`, a submit button, and the saved line.
  - **`POST /ask`.** The answer page. The app reads the raw body (`await request.body()`), decodes it as UTF-8 with `errors="replace"`, and parses it with `urllib.parse.parse_qs` (no python-multipart). `q` defaults to "" and `prev` is optional. The client key is `client_key(request.client.host)`.
  - **`GET /evidence/{unit_id}`.** One corpus unit: its subject's display name, `when`, claim and detail. An unknown id gets status 404 with a page that shows `OFF_TOPIC_TEXT` and the box.
  - **`GET /health`.** JSON from `desk.health()`.
- **The answer page shows four things:**
  1. **What was asked.** A question shows its text. A job description shows "Requirements read from your job description" and the requirement list, not the posting.
  2. **The answer.** Each kept claim appears as in `render_text`, and each cited unit is a link to `/evidence/<id>`. A jd claim shows `need → text`. Fixed outcomes show their fixed string. A fallback shows its intro and its unit claims, each linked.
  3. **`NEXT_STEP`.** The resume and the email are links.
  4. **The box again.** It carries a hidden `prev` field only when the outcome is `answer`, plus the saved line.
- **Status codes:** `Served.status`. A 429 also sets `Retry-After`.
- **Templates:**

## Decisions made in this plan (Claude's calls; Mike can overrule)

- **The DTD release ships first.** It is built here, but ships only at Task 9 with Mike's go, so the whole plan has a single stop. DTD owns the base Caddyfile, because it was on the box first.
- **The link rule lives in grounding, not privacy.** A domain a cited unit states, such as the GPTee shop or deals.forn.al, may appear; any other may not. forn.al and its subdomains always pass. `first_person` still skips "us" (it collides with "US"), and VERDICT's `N/10` still hits dates; both fail closed and are left alone.
- **Follow-ups are stored server-side.** The box sends back only an unguessable answer id (`prev`), never turn text, so a visitor can't forge context. Text from an unknown id is ignored.
- **The cache holds only `answer` outcomes**, keyed by everything that shapes an answer. A cached answer is still served when the cap is reached, as in DTD.
- **Limits use DTD's values:** 20 asks per hour per address, 60 fresh model calls per hour in all, and 2 at once. The day cap is $1.50, a tenth of the month cap, as in DTD. Rate-limited (429) and busy (503) visitors get the fallback page, as the spec says.
- **The index is built locally and shipped as a sha-checked bundle**, as DTD ships `live.db`. The service refuses a stale index, because `open_index` checks the corpus and the model.
- **`MemoryMax=1200M`.** DTD's measured peak is about 530 MB under a 2G cap, on a 3.8 GB box.
- **Jinja2 with autoescape** renders the pages. The form body is parsed by hand, because python-multipart isn't needed for a single text field.
- **A job-description answer page shows the requirement list**, not the posting, which matches what the model saw.
- **Wait state.** The plain form post shows the browser's own loading state; no JavaScript is added. The copy pass in M4 may add a line under the button.
- **The smoke test's one live question** costs about one Haiku answer, unless it is cached.
